# twflow — 台股法人資金流向儀表板

盤中把各板塊的資金流向畫成**四象限輪動圖**（加速流入／流入但放緩／加速流出／
流出但放緩），收盤後用證交所官方三大法人數據**校準推估值**並顯示準確度。

---

## ⚠️ 先讀這段：盤中數字是推估值

**台股沒有公開的盤中法人買賣超資料。**

- 證交所三大法人逐檔買賣超（T86）**收盤後**（約 15:00–16:00）才發布
- 券商分點（BSR）同樣是盤後，而且需要通過圖形驗證碼

盤中真正拿得到的只有成交價、成交量與五檔委買委賣。所以本工具（以及市面上
任何宣稱有「盤中法人動向」的產品）在盤中做的都是**推估**：把成交價和當時掛在
盤上的委買委賣價比對，成交在賣價附近算「主動買」、成交在買價附近算「主動賣」，
再乘上成交金額。這是 Lee-Ready 演算法的快照版變體。

三個必須知道的限制：

| 限制 | 說明 |
|---|---|
| **主動買 ≠ 法人買** | 主動方可能是散戶、當沖客或程式單。這只是「誰比較急著成交」的代理指標。 |
| **快照不是逐筆** | MIS 每 5 秒才更新一次，一個區間內的多筆成交只能用單一價格代表。 |
| **爆量 ≠ 大單** | 快照看不到個別委託大小。`burst_*` 欄位代表的是「該區間成交量超過門檻」。 |

因此本工具**不把推估當成事實**：每天收盤後會拿當天的推估值和官方三大法人買賣超
比對，算出**等級相關係數（Spearman）**與**方向一致比例**，直接顯示在儀表板上。
這個數字不會永遠是高的——它就是要讓你自己判斷今天的圖能信到什麼程度。

**本工具僅供研究參考，不構成任何投資建議。**

## 快速開始

```bash
pip install -e .
cp config.example.yaml config.yaml     # 把 mode 改成 live
```

### 先看看長什麼樣子（不需外網）

```bash
twflow demo --days 5      # 產生合成示範資料
twflow serve              # http://127.0.0.1:8000
```

> `demo` 產生的是**合成資料**，不是真實行情。只用來檢視介面與驗證管線。

### 接真實資料

```bash
twflow doctor             # ① 檢查 8 個資料來源的可達性與欄位結構
twflow record             # ② 把真實回應錄進 fixtures/
pytest                    # ③ 用真實樣本重跑 parser 測試  ← 關鍵驗收點
twflow sync               # ④ 匯入證券清單與官方產業別
twflow eod --date 2026-08-27   # ⑤ 抓一天盤後數據，人工比對證交所網頁
twflow auto               # ⑥ 盤中輪詢 + 收盤後自動跑盤後流程
twflow serve              # ⑦ 開啟儀表板（另開一個終端機）
```

### 日常使用：`twflow auto`

`twflow auto` 是實際每天在跑的指令。它依時鐘決定該做什麼：

| 時間 | 動作 |
|---|---|
| 09:00–13:30 | 輪詢即時報價，累積盤中資金流 |
| 16:00 之後 | 跑當日盤後流程（官方三大法人數據 + 校準） |
| 其餘時間 | 等待 |

跨日、假日、程式中途重啟都會正確接續——「今天盤後跑過了沒」是查資料庫，
不是記在記憶體裡，所以重開機也不會重複或漏跑。

想手動控制的話，`twflow poll` 與 `twflow eod` 仍然可以個別使用。

### 為什麼 ①②③ 是必要的

**這份程式碼是在連不到台股資料源的環境寫的**（開發環境的網路政策擋掉了
twse／tpex／taifex）。所有端點網址與欄位結構都是依公開文件和社群慣例實作的，
**沒有對照真實回應驗證過**。

所以：

- `twflow doctor` 會逐一打每個端點，印出實際拿到的欄位結構。欄位對不上時，
  錯誤訊息會直接列出**實際觀察到的欄位名稱**，照著改對應的 parser 即可。
- `twflow record` 把真實回應存進 `fixtures/`，之後 `pytest` 就是在真實結構上跑。

parser 都寫成**依欄位標題比對**而非欄位索引，所以證交所調整欄位順序不會讓它
靜默算出錯的數字——會直接報錯。但欄位**改名**仍需要你動手，`doctor` 就是用來
第一時間發現這件事。

各來源對應的檔案在 `src/twflow/sources/`：

| 來源 | 檔案 | 時效 |
|---|---|---|
| MIS 盤中即時報價 | `mis.py` | 盤中 ~5 秒 |
| 上市三大法人買賣超 (T86) | `twse_t86.py` | 盤後 |
| 外資持股比率 (MI_QFIIS) | `twse_qfiis.py` | 盤後 |
| 上市／上櫃公司產業別 | `twse_meta.py` | 每日 |
| 上櫃三大法人買賣超 | `tpex_insti.py` | 盤後 |
| 期貨三大法人未平倉 | `taifex.py` | 盤後 |
| 券商分點（選配） | `bsr.py` | 盤後，手動匯入 |

### 回補歷史

校準係數需要每檔至少 5 個交易日的樣本才會生效，一天一天跑太慢：

```bash
twflow eod --since 2026-07-01 --until 2026-08-27
```

週末自動跳過，中間某天失敗（非交易日、來源改版）只會記錄下來，不中斷整個區間。

> **盤中推估資料無法回補。** 證交所沒有提供歷史逐筆或分時報價，推估值只能在
> 當天盤中即時累積。所以回補出來的是官方三大法人數據，校準要等你實際盤中跑過
> `twflow poll` 之後才會有樣本可比——**第一天不會有準確度數字**。

## 怎麼看四象限圖

每個泡泡是一個板塊，位置由兩個問題決定：

- **橫軸 · 強度** — 今天資金淨流入還是淨流出？往右＝買方積極，往左＝賣方積極
- **縱軸 · 動能** — 這股力道正在變強還是變弱？往上＝比前一段時間更積極

強度用的是**淨流入佔該板塊成交值的比重**，不是絕對金額。這樣半導體和水泥才能
放在同一張圖上比較——否則台積電所屬的板塊會永遠在角落，其他全擠成一團。

| 象限 | 條件 | 意義 |
|---|---|---|
| 右上 **加速流入** | 強度 > 0，動能 > 0 | 資金持續買進，而且越買越積極 |
| 右下 **流入但放緩** | 強度 > 0，動能 < 0 | 還在買，但力道正在減弱 |
| 左下 **加速流出** | 強度 < 0，動能 < 0 | 賣壓持續，而且越來越重 |
| 左上 **流出但放緩** | 強度 < 0，動能 > 0 | 還在賣，但賣壓正在收斂 |
| 灰色 **動能待觀察** | 歷史不足 | 強度有效，但還算不出加速度 |

泡泡大小＝板塊成交值。動能的比較視窗預設 30 分鐘，可在畫面上切換。

### 鑽取板塊成分股

點四象限圖上的泡泡、或點左下角的板塊排行，個股排行就會切換成該板塊的成分股，
回答「這個板塊是被哪幾檔帶動的」。再點一次同一個板塊、或按「← 看全部個股」
即可回到全市場。

### 輪動軌跡

四象限圖是某一瞬間的切片，看不出「這個板塊是從哪裡移動過來的」——但輪動的
重點正是**移動方向**。勾選「顯示輪動軌跡」後，前 6 大板塊會拉出一條尾巴，
串起它在過去每隔 20 分鐘的位置，點越大越接近現在。

同樣落在「加速流入」，一個是從左下角一路衝上來、另一個是從更高處掉下來，
意義完全不同。

每個軌跡點都是用「當時為止的資料」重算的，等於當時的儀表板真的會顯示的位置，
不是事後回推的平滑曲線。

### 開盤初期的動能

動能是「近 W 分鐘的強度」減「前 W 分鐘的強度」，需要 2W 分鐘的歷史。開盤後
還不到 2W 分鐘時，前段視窗是空的——如果照樣硬算，動能會退化成強度本身，
於是**所有淨流入的板塊都會被標成「加速流入」**，而畫面看起來完全正常。

本工具的處理方式是把已經過去的時間對半切（例如開盤 10 分鐘就比較「近 5 分鐘」
與「前 5 分鐘」），並在畫面上標示實際使用的視窗長度。連對半切都不夠時
（開盤前 4 分鐘），板塊會被標為**動能待觀察**顯示成灰色，而不是硬塞一個象限。

## 板塊分類

分兩層：

1. **官方產業別**（約 32 類）— 由證交所／櫃買 API 自動抓取，可靠
2. **自訂細分板塊** — 定義在 `sectors.yaml`，覆蓋在官方分類之上

沒有列在 `sectors.yaml` 的個股會自動沿用官方產業別，所以即使完全不編輯它，
儀表板一樣能運作，只是顆粒度較粗。

> **請校對這份對照表。** `sectors.yaml` 內建 54 個板塊、246 檔個股，是人工整理的，
> **可能有錯**。分類錯誤會讓該檔的資金流被算進錯的板塊，而畫面上看不出異狀。
> 建議照自己的認知校對一遍，特別是你實際會交易的標的。改完重新整理頁面即可生效，
> 不需要重啟伺服器。
>
> 另外：官方**沒有**「108 板塊」這種東西，新聞裡的 108 是那個 App 自訂的分類數。
> 要更細就往 `sectors.yaml` 加：
>
> ```yaml
> sectors:
>   矽光子: ["4979", "3363", "6869"]
> ```

## 券商分點與官股動向（選配）

證交所的分點資料需要通過圖形驗證碼，自動化既不穩定也不妥當，所以採**手動匯入**：

1. 到 [BSR](https://bsr.twse.com.tw/bshtm/) 查詢個股、下載 CSV
2. 存成 `data/bsr/YYYY-MM-DD_股票代號.csv`（例如 `data/bsr/2026-08-27_2330.csv`）
3. `twflow eod` 會自動讀取

「官股動向」由公股行庫券商分點彙總得出，名單可在 `sectors.yaml` 的
`state_brokers` 調整——不同資料來源對「官股」的認定範圍略有差異。

分點失敗**不影響**盤中推估與三大法人主流程。

## 設定

`config.yaml`（完整選項見 `config.example.yaml`）：

```yaml
mode: live               # live / fixture / record
markets: [TWSE, TPEX]

poll:
  interval_seconds: 60   # 全市場掃一輪的目標週期
  batch_size: 50         # 單次 MIS 請求帶幾檔
  universe: all          # all 或 watchlist（只掃自選股，更新更快）

flow:
  burst_lot_threshold: 100
  apply_calibration: true

quadrant:
  momentum_window_minutes: 30

watchlist: ["2330", "2317", "2454"]
retention_days: 30
```

**關於輪詢節奏**：MIS 限流約 3 requests / 5 秒。上市＋上櫃約 1,800 檔，每批 50 檔
就是 36 個請求，一輪約 60 秒。輪詢間隔越長，單一價格代表整段區間的誤差越大——
所以 `universe: watchlist` 只掃自選股時可以把間隔縮到 5–10 秒，推估會明顯更準。

## 架構

```
src/twflow/
├── flow.py         內外盤 tick rule 分類（推估的核心）
├── quadrant.py     四象限座標與分類
├── sectors.py      兩層板塊分類與彙總
├── calibrate.py    盤後校準：Spearman、方向一致率、迴歸係數
├── poller.py       盤中輪詢迴圈
├── pipeline.py     盤後流程協調（單一來源失敗不中斷整批）
├── store.py        SQLite（每分鐘彙總，非原始快照）
├── httpclient.py   限流、重試、live/fixture/record 三模式
├── api.py          FastAPI 後端
└── sources/        各資料來源的抓取與解析
web/                儀表板前端（ECharts 已 vendor，離線可用）
```

盤中原始快照不落地——量太大又沒有分析價值。只存**每分鐘彙總**
（約 1,800 檔 × 270 分鐘 ≈ 每交易日 50 萬列），依 `retention_days` 清理。

## 開發

```bash
pip install -r requirements-dev.txt
pytest                      # 217 個測試，全程離線
twflow fixtures             # 重新產生合成 fixture 樣本
twflow --mode fixture doctor   # 離線跑診斷
```

測試分兩類：**演算法測試**用構造好的、已知答案的輸入驗證分類邏輯與統計量；
**parser 測試**驗證欄位改名、順序調換、民國／西元年混用時不會靜默算錯。

## 讓它每天自己跑

`twflow auto` 需要長時間執行。以 systemd 為例（Linux）：

```ini
# ~/.config/systemd/user/twflow.service
[Unit]
Description=twflow 台股資金流向

[Service]
WorkingDirectory=%h/legal-entity
ExecStart=%h/legal-entity/.venv/bin/twflow auto
Restart=always
RestartSec=30

[Install]
WantedBy=default.target
```

```bash
systemctl --user enable --now twflow.service
journalctl --user -u twflow -f
```

macOS 用 launchd、或直接 `tmux new -s twflow 'twflow auto'` 也可以——
重點是讓它在盤中持續跑，因為**盤中推估資料無法事後回補**。
